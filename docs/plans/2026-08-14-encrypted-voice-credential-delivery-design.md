# Encrypted voice credential delivery

The invited-agent detail page provides an owner-only operator control for rotating a voice gateway credential without returning plaintext to the browser. The operator generates an ephemeral key pair on the intended gateway and pastes only its public key. The existing Firebase-authenticated API request binds rotation to the agent owner and sends that public key to the encrypted rotation endpoint.

The API contract is `POST /api/agents/:agentId/voice-credential/rotate-encrypted-delivery` with exactly `{ publicKeyPem }`. Its response is reduced to an allow-list of safe delivery metadata. The UI never requests, renders, logs, stores, exports, or copies the plaintext credential, private key, or ciphertext. The operator must explicitly acknowledge that the key belongs to the intended Bragi gateway and that rotation invalidates the previous credential. While the request is active, controls show an explicit progress state and prevent duplicate submissions.

The production bootstrap is restricted to the canonical Bragi agent and uses `POST /api/agents/:agentId/voice-credential/rotate-encrypted-delivery`. The API returns only delivery ID, claim ID, algorithm, the canonical `perkos-voice-gateway-grant:v1` audience, public-key fingerprint, and expiry. The browser allow-lists that response, clears the pasted public key and acknowledgement after success, and displays only safe status metadata. Ciphertext is pulled directly by Bragi and is never returned, rendered, copied to the clipboard, logged, or persisted by Web.

Authorization remains server-enforced. The panel renders only for canonical `Bragi` when the connected wallet matches the agent owner, while the API independently verifies Firebase owner identity, invited-agent ownership, and the configured Bragi enrollment. Tests cover owner and Bragi gating, explicit acknowledgement, allow-listed delivery metadata, sensitive input clearing, and absence of clipboard controls.
